# Experiment 3 — Robustness to Data Uncertainty

Версия протокола: `experiment3-robustness-1.0.0`. Данные и классификация остаются предварительными / Unverified. Альтернативные уровни — допущения, а не наблюдения. Устойчивость модели не означает правильность рекомендаций.

## Дизайн и независимые исследования

Пять контролей: (τ, λ) = (1,1), (2,1), (3,1), (4,1), (4,2). Последний — дополнительная stress-проверка, а не утверждение о фактической чувствительности конкретного датасета. Все 14 профилей и 182 направленные пары; алгоритм Kahn с лексикографическим разрешением равенств, scope All. Пользователь выбирает только зафиксированную версию.

| Исследование | Сценарии | Неизменные факторы | Количество |
| --- | --- | --- | --- |
| A | A0: unknown source=0, A1: =1, A2: =2 | Final v2, граф G1/G2/G3 | 3 × 3 × 5 = 45 |
| B | B0: Final v2, B1: role_skill_weights, B2: единичные веса | unknown source=0, граф G1/G2/G3 | 3 × 3 × 5 = 45 |
| C | G1 без одного из 51 исходных рёбер | Final v2, unknown source=0 | 51 × 5 = 255 |

Итого **345 сценариев, 62 790 оценок переходов**. A0 и B0 представлены раздельно для аудита независимых сравнений, хотя соответствующие значения совпадают. Для A baseline=A0, для B baseline=B0, для C baseline=A0/G1 — всегда при тех же τ/λ и, для A/B, том же графе. Сценарии не комбинируются между исследованиями.

G1/G2/G3 используют существующий неизменный протокол: 51/14/50 рёбер, одинаковые 71 вершина. Версии с изменённой популяцией рёбер требуют отдельной классификации и не допускаются этим протоколом. Исправленные требования при том же графе допускаются.

## Временные конфигурации без изменения формул

`services/experiment3.py` создаёт временный Snapshot с простыми Python-записями и вызывает существующий `run_experiment`, далее неизменные compare/M1/M2/M3. ORM-объекты, CSV, версии и подтверждения записей не изменяются. В математическом ядре новых ветвей нет.

A1/A2 заполняют только отсутствующие индивидуальные требования исходного профиля и явно null исходные уровни. Известный нулевой уровень остаётся нулём. Подстановка применяется только к source конкретной пары: тот же профиль в позиции target использует исходные требования. Неизвестный target=4, исключение неоднозначных групп и существующий fallback веса=1 сохраняются.

B0 использует существующий MAX(weight_0_1) после skill_mapping. B1 использует только `role_skill_weights.csv` выбранной целевой роли. B2 создаёт полное временное покрытие навыков/ролей весом 1; фактического fallback нет. Для вызова существующего API B2 использует временный внутренний ключ Final v2; внешний descriptor явно фиксирует `weight_source=unit`, `weight_mode=B2` и хеш вмешательства. Никакие единичные записи не сохраняются в SkillWeight.

**Нормализация не выполняется.** Она не нужна для воспроизведения исходных формул и сравнения исходных источников как альтернативных допущений. Абсолютная разница B включает эффект общей массы весов, а не только относительной важности навыков. Это не общая эмпирически откалиброванная шкала. По каждому источнику/роли сохраняются count, min/max, sum/mean, normalization=none. Нельзя интерпретировать более низкие значения одного источника как более простые переходы. Ранги анализируются отдельно.

C использует существующий механизм временного исключения одного ребра из полного G1, не изменяя именованные конфигурации и CSV. Для каждого исключения сохранён отдельный config с parent hash, исключённым ID, всеми оставшимися ID и хешем. Все вершины остаются. Общий baseline M2 не зависит от исключённого ребра.

## Метрики и неопределённость

Для **обеих M2 и M3** сохраняются средняя оценка, baseline mean, знаковая средняя разница (scenario−baseline), средняя и максимальная абсолютная разница, число изменившихся пар, Spearman и Kendall τ-b, пересечения Top-3/Top-5, изменения состава/порядка и заменённые цели.

Корреляции считаются по 13 целям отдельно для каждого исходного профиля. Средние ранги для равных оценок, Kendall τ-b с ties. Неопределённые коэффициенты — null (пустые ячейки CSV), исключаются из средних; счётчики неопределённых источников сохранены. Top-K при равных расстояниях использует лексикографический ID цели. По числу заменённых целей и числу источников с изменённым Top-K нельзя судить как об одной метрике.

Счётчики unknown и fallback — **число обращений к навыкам в парах**, с повторениями между переходами, не число людей и не число уникальных навыков датасета. Для каждой пары сохраняются исходная неизвестная популяция, список/число использованных исходно неизвестных навыков, число подставленных A1/A2 значений и реально использованных fallback весов. Актуальная область обращения может измениться при изменении дефицита/замыканий. Эти значения не скрываются после подстановки. Неизвестность target также сохраняется отдельным счётчиком.

51 ребро ранжируется отдельно для каждого контроля по (1) средней абсолютной разнице M3, (2) потере Spearman, (3) числу источников с изменённым Top-3, (4) Top-5. Неопределённый Spearman не получает места. Равенства влияния упорядочиваются ID ребра: соседние места при равной метрике не означают различия влияния. Kendall, максимальное изменение и затронутые пары также доступны. Отсутствие эффекта в этих условиях не доказывает ненужность связи.

## Хранение и API

- `POST /api/experiments/experiment3`, JSON `{"version_id":"<64-character version ID>"}`; дополнительные параметры отвергаются.
- Используется существующая таблица ExperimentRun, новый kind `experiment3`, без изменения схемы БД. Один envelope хранит все 345 сценариев и полные результаты; каждый сценарий имеет стабильный ID, baseline ID и configuration hash. Повторный запуск возвращает сохранённый результат.
- `/api/runs/{run_id}` загружает envelope; Experiment 1/2 не пересчитываются и не перезаписываются.
- Provenance фиксирует dataset/version, record/status hash, source manifest hash, classification hash, полные конфигурации и LOO edge IDs, параметры, правила, математическую версию 1.1.0, версию анализа, runtime и исходный manifest. Source hash и record hash исправленной версии — разные сведения.

`GET /api/experiments/experiment3/{run_id}/exports/{filename}`:

| Файл | Строки данных / содержимое |
| --- | --- |
| experiment3-summary.csv | 345 сценариев, метрики M2/M3 и счётчики |
| experiment3-results.csv | 62 790 пар с baseline оценками, разницами и списками неизвестных/fallback |
| experiment3-rankings.csv | 9 660 строк: 345 × 14 источников × 2 модели; Top-K, коэффициенты и JSON-список 13 рангов целей |
| experiment3-edges.csv | 255 рейтингов рёбер: 51 × 5 контролей |
| experiment3-results.json | Полный envelope и provenance |

CSV содержит параметры вмешательства, τ/λ, run/scenario/baseline/configuration IDs, хеши, версии и правило весов. Для восстановления точных конфигураций и provenance нужно сохранять также JSON. Экспорт читает сохранённые результаты, не рассчитывает M3 заново. Полный JSON/CSV может быть большим: 62 790 пар и 9 660 профильных сравнений.

## Интерфейс и изображения

Research Results → **Experiment 3 — Data Robustness**. Загрузка исторических запусков, A/B/C, выбор G1/G2/G3 и M2/M3; для C фиксированы G1 и M3. Матрицы по пяти контролям: средняя абсолютная разница или Spearman. Общая шкала A/B охватывает все три графа выбранного исследования/модели; шкала Spearman −1…1.

Линии A/B показывают основной протокол λ=1; stress-результат τ=4/λ=2 находится в таблице и пятом столбце heatmap. Для C доступны Top-10 на графике и все 51 связи в рейтинге, выбор контроля и критерия. Полная heatmap C содержит 51 строку, прокручивается на экране и экспортируется полностью.

SVG/PNG текущих фигур используют существующий проверенный механизм с маркерами, переносом подписей и provenance. В metadata записаны отображаемые настройки, ID/config hashes сценариев и допущения; PNG содержит iTXt и 300 dpi. Пустые/неопределённые значения не становятся нулём. Для статьи предпочтителен SVG. Длинную матрицу из 51 строки нужно компоновать на странице статьи самостоятельно; отсутствие обрезания не гарантирует читаемость при уменьшении до одной колонки.

## Ручная проверка пользователем

1. Из корня выполнить `docker compose up -d --build`. Самостоятельно открыть приложение на порту 8080.
2. Выбрать исходную версию либо версию требований с теми же 51 связями. Research Results → Experiment 3 → расчёт. Проверить 345 сценариев / 62 790 оценок, сохранение и повторную загрузку.
3. A: проверить A0/A1/A2 отдельно для каждого графа и M2/M3; известные нули не должны превращаться в 1/2. Сверить счётчики неизвестных и допущений в CSV/JSON.
4. B: переключить источники, проверить диагностику массы/диапазонов весов и normalization=none. У B2 fallback=0. Не трактовать меньшие абсолютные оценки как лучший источник.
5. C: проверить G1-only, по одному исключению, все 51 связи при каждом из пяти контролей; M2_difference=0. Сменить критерии влияния, проверить Top-3/Top-5, неопределённые коэффициенты и пятый stress-столбец.
6. Скачать все пять файлов, сверить количества строк и IDs/hashes, экспортировать SVG/PNG A/B и C. Проверить длинные подписи, все серии, полную высоту матрицы C, metadata/iTXt и целевой размер IEEE.
7. Загрузить прежние Experiment 1/2 и убедиться, что их значения/run IDs сохранились.

Приложение, Docker, серверы и браузер разработчиком не запускались. Проверены только изолированные расчёты SQLite, DOM/SVG в jsdom и production build. PostgreSQL/pgvector и PNG Canvas в настоящем браузере проверяет пользователь.
