# IT Career Graph Lab — GitHub Pages edition

## Вывод архитектурного аудита

Перенос вычислений в браузер возможен без изменения математической методологии. Python-ядро работает с конечными списками навыков, рёбрами, требованиями и весами. FastAPI — транспорт, PostgreSQL — хранение, а используемые функции NetworkX заменяются обходами DAG с тем же порядком. NLP/ML-модели не участвуют в MVP и не требуются публичной сборке.

Создан отдельный TypeScript-порт, не замена Python-реализации. Сохраняются M1 (число положительных прямых дефицитов), M2 (сумма весов × нормированный дефицит), M3 (M2 + λ × отдельная prerequisite-нагрузка), исключение неоднозначных групп, явный консервативный сценарий неизвестных уровней, unit fallback и правило MAX Final v2. Транзитивное замыкание, устранение повторного учёта, Kahn и DFS, сортировка и Top-K воспроизведены. Метрики используют средние ранги при точных совпадениях и Kendall τ-b; неопределённые корреляции остаются null.

Побитовая идентичность всех статистик между NumPy и JavaScript не обещается. Критерий: `abs(browser−python) ≤ 1e-10 + 1e-10 × abs(python)`. Идентификаторы навыков/рёбер, составы множеств, порядок обучения, ранги и Top-K сравниваются отдельно; epsilon для объединения рангов не вводится.

Python 3.11 использует обычное последовательное суммирование, Python 3.12 — компенсированное. Публичный снимок фиксирует `reference_python` и `model_summation`; браузер выбирает соответствующую реализацию арифметики. Это воспроизведение поведения исходного движка, не изменение формулы. Поведение 3.12 сверено с [исходником CPython](https://github.com/python/cpython/blob/3.12/Python/bltinmodule.c). Workflow генерирует эталон в Python 3.12 и блокирует публикацию при несовпадении тестов; локальная проверка выполнена в доступном Python 3.11.9.

## Два независимых режима

| Свойство | Локальный | GitHub Pages |
| --- | --- | --- |
| Запуск | Docker/FastAPI/PostgreSQL | Статические файлы GitHub Pages |
| Модели | Существующий Python | TypeScript в Web Worker |
| Источник | Версии БД, импорт CSV | Один опубликованный JSON-снимок исходных CSV |
| Запуски | ExperimentRun в PostgreSQL | Map только в памяти Worker |
| Редактирование / верификация | Сохраняет версии и историю | Недоступно; показывается read-only provenance |
| Экспорты | CSV/JSON/SVG/PNG | CSV/JSON/SVG/PNG, новые браузерные расчёты |

Обычные команды и Docker Compose не менялись. `npm run build` строит локальный frontend с прежним API. `npm run build:pages` задаёт `base=/ITCareerGraphLab/`, флаг публичного режима и блокирует загрузку `.env` средствами Vite. Внешний backend и БД публичному сайту не нужны.

### Путь данных и вычислений

1. `scripts/prepare_pages.py` читает ровно десять файлов из `datasets/`, используя существующий импортёр в новой SQLite **в памяти**. Он не подключается к существующей PostgreSQL, не извлекает частные версии и не читает историю настоящих ExperimentRun.
2. Генерируются `frontend/public/data/published.json` и `manifest.json`: нормализованные входы, оригинальные строки CSV, статусы/происхождение, качество, полные G1/G2/G3, dataset/record/classification/source hashes. Все исходные статусы остаются Unverified, `min_level` связей — null. `imported_at=null` явно означает, что реальная дата локального импорта неизвестна публичному снимку и не публикуется.
3. Worker загружает только эти два JSON со своего origin и проверяет SHA-256 до создания сессии. Входные объекты рекурсивно замораживаются. Неправильная версия или повреждённый снимок вызывают ошибку, не подстановку демонстрационных значений.
4. Существующие React-страницы вызывают публичный адаптер. Их API-пути обрабатываются **внутри Worker**, а не через HTTP `/api`. Все переходы и эксперименты действительно рассчитываются по входам пользователя. Кэш внутри вкладки переиспользует только ранее выполненные в этой вкладке вычисления.
5. Экспорты читают рассчитанные в памяти значения и содержат provenance. Browser run IDs имеют префикс `browser-`, SHA-256 и отдельную `browser_implementation=browser-models-1.0.0`. Они намеренно не выдаются за backend run IDs. Математическая версия 1.1.0 и версии протоколов экспериментов сохраняются отдельно.

В `frontend/.parity/reference.json.gz` находятся **только тестовые** ожидаемые результаты Python. Они не импортируются кодом Worker, игнорируются Git и не попадают в `dist`. Поля публичного JSON проверяются по allowlist, в нём нет подготовленных сценариев M1/M2/M3. Существующие научные результаты и частная история остаются в локальной версии и не перезаписываются.

## Возможности публичного сайта

- Dashboard с реальными показателями опубликованного набора и предупреждениями качества.
- Skill Graph Explorer: G1/G2/G3, типы связей, полный/локальный режим, глубина, поиск, зависимости, пути, позиции и экспорт.
- Career Transition Explorer: 14 профилей / 182 пары, M1/M2/M3, Top-3/5, сравнение M2/M3, вычисляемые дефициты.
- Research Experiments: τ/λ, оба исходных источника весов, Kahn/DFS, временное исключение/добавление связей в Legacy; циклы отвергаются.
- Research Results: обычный массовый протокол, Experiment 1 G1/G2/G3, Experiment 2 (60 сценариев), Experiment 3 (345 сценариев A/B/C), таблицы/heatmap/графики и экспорт.
- Data & Provenance: качество и оригинальные строки каждого из десяти источников; дополнительная страница read-only записей с происхождением.

**Ограничения:** опубликована одна исходная версия. Административное создание/редактирование/верификация и сравнение с неопубликованными исправленными версиями недоступны. Нельзя выставить Expert Verified или Source Verified. Verified-only scope честно сообщает отсутствие покрытия, как локальный движок для этого набора. Пользовательские интервенции меняют только временную конфигурацию расчёта, не эталонный граф.

Запуски, параметры и позиции графа исчезают после перезагрузки. Нет регистрации, localStorage, IndexedDB или записи на сервер. Для сохранения нужны CSV/JSON/SVG/PNG. Тяжёлые исследования могут занять время и память на устройстве посетителя; Worker сохраняет отзывчивость интерфейса, но мобильное устройство может иметь меньшие ресурсы.

Данные преимущественно подготовлены ИИ и не прошли экспертную проверку. Веса не означают время обучения. Устойчивость и выполнение пререквизитов не доказывают качество рекомендаций. Сценарии неизвестных уровней не являются измерениями.

## Маршрутизация и ресурсы

Используются hash-ссылки, которым не требуется серверный rewrite:

- `https://<username>.github.io/ITCareerGraphLab/#/dashboard`
- `https://<username>.github.io/ITCareerGraphLab/#/skills`
- `https://<username>.github.io/ITCareerGraphLab/#/career`
- `https://<username>.github.io/ITCareerGraphLab/#/experiments`
- `https://<username>.github.io/ITCareerGraphLab/#/results`
- `https://<username>.github.io/ITCareerGraphLab/#/data`
- `https://<username>.github.io/ITCareerGraphLab/#/versions` — read-only provenance.

Именно `#/skills`, а не физический `/skills`, является прямой ссылкой страницы. Браузер запрашивает существующий корневой HTML, затем React выбирает раздел; обновление страницы работает без 404 и внешнего сервера.

Все JS/CSS, Worker и данные используют `/ITCareerGraphLab/`. Публичная сборка не загружает Google Fonts, использует системный fallback; локальный дизайн со шрифтами сохранён. CSP ограничивает script/Worker/connect своим origin; inline styles разрешены для React Flow/Motion, blob/data изображения — для экспорта. Шрифты, аналитика, CDN и внешние вычислительные API публичной версии не требуются.

## Сборка и проверки без запуска приложения

Из корня проекта, с установленными Python-зависимостями backend и npm-зависимостями frontend:

```bash
.venv/bin/python scripts/prepare_pages.py --references
PAGES_PARITY=1 npm test --prefix frontend
npm run build:pages --prefix frontend
python3 scripts/check_pages.py
```

В CI используется Python 3.12 вместо локального `.venv`. `--references` выполняет существующие backend-функции в изолированной SQLite; сервер не запускается. `PAGES_PARITY=1` делает отсутствие эталонов ошибкой, а не пропуском теста. Без этого флага обычные frontend-тесты могут пропустить пять сравнительных тестов, если `.parity` ещё не создана.

`check_pages.py` читает готовые файлы: проверяет base и существование entry/chunk/Worker ресурсов, SHA JSON, десять исходных CSV, 71/14/51 и G1/G2/G3, отсутствие внешнего font import, CSP и allowlist содержимого артефакта. `.env`, `.parity`, БД, Docker-конфигурации, Python-исходники, приватные данные и старые результаты в артефакт не копируются. Сборка Pages проверена с фиктивным `VITE_API_URL`; строка не попала в выходные JS.

[Подробный отчёт о тестах и перечень файлов](github-pages-verification.md).

## Создание репозитория и публикация пользователем

Эти действия подготовлены инструкцией; агент их **не выполнял**.

1. В своём GitHub создать **публичный** репозиторий с точным названием `ITCareerGraphLab`. Не создавать там README автоматически, если собираетесь отправлять этот существующий проект.
2. В локальной папке проверить `git status`. Если Git ещё не инициализирован, выполнить `git init -b main`. Если репозиторий уже существует, сохранить его историю и использовать основную ветку `main` для данного workflow.
3. Добавить только проверенные файлы проекта. Например:

   ```bash
   git add .gitignore .github README.md backend frontend datasets docs scripts docker-compose.yml
   git diff --cached --name-only
   git diff --cached --stat
   ```

   Перед commit просмотреть список: не включать реальные `.env`, токены, ключи, приватные версии/выгрузки или персональные каталоги. `node_modules`, `.venv`, `dist`, `.parity`, `.env` и `.env.*` уже игнорируются. Не использовать `git add -f` для обхода этих правил. Исторические `reports/` не нужны для публичного сайта; решение о публикации научных архивов принимать отдельно.

4. После собственной проверки выполнить commit и подключить **свой** remote. Если remote уже настроен, не перезаписывать его вслепую:

   ```bash
   git commit -m "Prepare browser research edition for GitHub Pages"
   git remote add origin https://github.com/<username>/ITCareerGraphLab.git
   git push -u origin main
   ```

5. В GitHub открыть **Settings → Pages → Build and deployment → Source → GitHub Actions**. Порядок настройки соответствует [официальному руководству GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages); путь `base` — [руководству Vite](https://vite.dev/guide/static-deploy#github-pages).
6. В **Actions** запустить `Validate and publish GitHub Pages`, если первый push произошёл до включения Pages. Далее push в main запускает сборку и публикацию автоматически; pull request только проверяется, без deployment. Build/job не запускает Docker или серверы. Deploy зависит от успешной сверки Python/TypeScript и аудита артефакта.
7. При необходимости подтвердить deployment environment `github-pages` по правилам своего аккаунта. Сайт будет доступен по `https://<username>.github.io/ITCareerGraphLab/`.
8. Выполнить ручной checklist ниже. Изменение имени репозитория требует согласованного изменения Vite base и `check_pages.py`; текущая конфигурация предназначена именно для `ITCareerGraphLab`.

## Ручная проверка после публикации

- Открыть корень и каждую hash-ссылку напрямую, обновить страницу, проверить Back/Forward. В Network убедиться, что нет запросов к localhost или `/api`, все данные/Worker идут с того же GitHub Pages origin.
- Dashboard: 71 навык, 14 профилей, 51 исходная связь; G1/G2/G3: 51/14/50 рёбер. Проверить статусы Unverified, легенду типов и source manifest.
- Skill Graph: поиск, локальный режим, глубина, фильтры, пути, drag/zoom и PNG/SVG.
- Career/Research: поменять роли, τ, λ, источник весов, Kahn/DFS; в Legacy исключить ребро. Проверить вычисленные значения и сообщения о циклах/Verified scope, не демонстрационные заглушки.
- Выполнить Experiments 1–3, проверить 182 пары, 60 и 345 сценариев. При λ=0 M3=M2. В Experiment 3 у C M2 не меняется, B2 не использует fallback.
- Скачать CSV/JSON и SVG/PNG с несколькими сериями/длинными подписями. Проверить числа, `browser-` run ID, dataset/source/record/config hashes, допуск и параметры. Проверить PNG при целевом размере IEEE; автоматические тесты Canvas не заменяют реальную проверку изображения.
- Открыть provenance: редактирования и подтверждения нет. Перезагрузить вкладку — пользовательские запуски исчезают, входной набор остаётся прежним. Экспортированные файлы сохраняются только по выбору посетителя.

Разработчик не запускал приложение, Docker, локальный сервер, браузер или browser automation. Настоящий deployment, браузерная проверка и загрузка файлов через браузер остаются пользователю.
