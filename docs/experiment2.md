# Experiment 2 — Parameter Sensitivity Analysis

Это дополнительный протокол `experiment2-sensitivity-1.0.0`. Математическое ядро M1/M2/M3 не изменено. Данные предварительные; устойчивость оценок не доказывает качество рекомендаций и не измеряет фактическую сложность или время обучения.

## Фиксированный дизайн

- Одна выбранная версия, 14 профессиональных профилей, все 182 направленные пары без диагонали.
- G1 Original: 51 связь; G2 Strict: 14 Required; G3 Extended: 50 Required + Recommended. Все 71 вершина сохранены. Типы связей остаются AI-assisted / Unverified, индивидуальные min_level не назначаются.
- τ = [1, 2, 3, 4], λ = [0, 0.25, 0.5, 1, 2]: ровно 60 сценариев, 10 920 оценок пар.
- `skill_weights_by_role_final_v2.csv`, MAX(weight_0_1) после существующего skill_mapping. Смешивания источников нет. Существующий явно сообщаемый fallback отсутствующего целевого веса = 1 сохранён; количество таких навыков включено в строки результатов.
- Kahn с лексикографическим разрешением равенств; scope All, включая Unverified, ручные изменения графа отключены.
- У групповых требований и неизвестных уровней остаётся прежняя семантика: группы исключены; неизвестный source=0 / target=4 — явно консервативный сценарий, не наблюдаемое владение.

`POST /api/experiments/experiment2` принимает только `{"version_id":"<64-character version ID>"}`. Остальные поля отвергаются. Сервис вызывает существующий `execute_relation_impact`, который использует `execute_run` и существующее M3. Независимой реализации M3 нет. При нарушении M3 ≥ M2, M3=M2 при λ=0, общей M2 или состава пар протокол завершается ошибкой, не меняя формулу.

Версии с изменённым составом исходных 51 связей не допускаются существующим контрактом G1/G2/G3. Версии с исправленными требованиями и тем же графом доступны. Подтверждение записей не выполняется автоматически.

## Метрики

Для каждого сценария сохраняются средние M2/M3, средний и максимальный M3−M2, B и λB, количество положительных нагрузок. B и M3−M2 различаются при λ=0.

Ранжирование рассчитывается отдельно для каждого из 14 источников по 13 целям, по возрастанию расстояния. Spearman использует средние ранги при точных совпадениях; Kendall τ-b учитывает связи. Константные ранги дают null, а не 0. Средние корреляции рассчитываются только по определённым коэффициентам; числа исключённых источников сохраняются.

Top-K при равенстве оценок разрешается лексикографическим ID цели. Раздельно сохраняются доля пересечения, количество источников с изменённым составом, с изменённым порядком и количество заменённых целей (left-minus-right). Это описательные метрики чувствительности, не метрики эффективности рекомендаций.

G1/G2, G1/G3 и G2/G3 сравниваются при одинаковых τ/λ. Знак `mean_score_change`: справа минус слева. M2 — единый baseline для всех графов и параметров. Абсолютные M1/M2 не сопоставляются на общей шкале.

## Хранение и воспроизводимость

Используется существующая таблица ExperimentRun, новый kind `experiment2`; миграция схемы не нужна. Сохраняются 60 batch, контролируемый G1/G2/G3 study и envelope Experiment 2. Повторный запуск с теми же параметрами возвращает сохранённый payload. Исходные CSV, прежние записи экспериментов и provenance не перезаписываются.

Envelope фиксирует dataset version, record/status hash, SHA-256 канонического source manifest (`source_data_hash`), classification hash, полные конфигурации с включёнными edge IDs и configuration hash, параметры, версию математического ядра 1.1.0, версию анализа, runtime и ссылки на batch run IDs. Source hash не заменяет record hash исправленной версии.

## Экспорт

`GET /api/experiments/experiment2/{run_id}/exports/{filename}` экспортирует только сохранённый запуск:

| Файл | Содержимое |
| --- | --- |
| experiment2-summary.csv | 60 агрегатов сценариев |
| experiment2-scenarios.csv | 10 920 значений пар, прямой дефицит и дополнительная нагрузка раздельно |
| experiment2-rankings.csv | 21 840 строк рангов целей: 10 920 M2/M3 и 10 920 сравнений графов, средние ранги и Top-3/5 |
| experiment2-results.json | Полный envelope, 60 сценариев, результаты, метрики по источникам и сравнения графов |

CSV содержит ID запуска/сценария, τ/λ, dataset/source/record/classification/configuration hashes, версии алгоритма и анализа, источник и правило весов, scope и отсутствие интервенций. Для сравнений графов указаны оба batch/configuration hash. Полные edge IDs и source manifest хранятся в JSON. Пустая ячейка коэффициента CSV означает неопределённость; JSON использует null. Ранги в CSV — детерминированная проекция сохранённых оценок через существующую `average_ranks`, без повторного расчёта M3.

В интерфейсе Research Results → Experiment 2 доступны шесть heatmap (нагрузка и Spearman для каждого графа), линии G1/G2/G3 по λ с выбором τ, таблицы Top-K, всех сценариев и графовых сравнений. Шкала нагрузки общая по всем 60 сценариям, Spearman фиксирована −1…1. Каждая фигура экспортируется в SVG/PNG; для четырёх τ последовательно выберите τ и экспортируйте линии.

SVG содержит полное provenance в metadata. PNG получает UTF-8 iTXt provenance и pHYs 300 dpi, целевую ширину минимум 2400 px при ограничении максимальной стороны 8192 px. Предпочтителен векторный SVG для статьи. Разрешение не означает проверку фактической печатной компоновки — размер и шрифт нужно проверить при вставке в IEEE-шаблон.

## Исправление старых графиков

Для ranking-comparison, sensitivity-curves, relations-sensitivity, relations-distribution используется статический SVG с заданными размерами. Это исключает зависимость экспорта этих фигур от измерения ResponsiveContainer и состояния анимации. Все конечные точки имеют маркеры, включая одиночную точку; постоянные шкалы расширяются. Отсутствующие значения дают разрыв/сообщение, а не нулевую оценку. Пустой график не экспортируется.

У архивов с независимо рассчитанными интервалами распределения новая view-проекция строит общие интервалы по сохранённым M2/M3. Она не изменяет исходный payload. Если пар нет, допускаются только совпадающие границы архивных интервалов; иначе показывается сообщение. CSV этой фигуры содержит именно показанные общие интервалы.

Подписи переносятся, легенды всех серий входят в SVG, высота и footer вычисляются по содержимому. Экспорт включает тот же SVG, который отображает значения. Причины первоначальных пустых фигур установлены как риски по анализу кода; конкретное поведение прежних браузерных запусков не воспроизводилось, поскольку запуск приложения запрещён пользователем.

## Ручная проверка пользователем

1. Запустить из корня `docker compose up -d --build`, открыть приложение на порту 8080 самостоятельно.
2. Выбрать исходную версию или версию требований с теми же 51 связями. В Research Results открыть Experiment 2 и нажать расчёт. Проверить 60 сценариев, 182 пары и 10 920 оценок.
3. Сопоставить λ=0: M3=M2, дополнительная нагрузка нулевая, Top-K не меняется. Проверить общую M2, переключение τ, одинаковые шкалы всех графов и обозначение неопределённых корреляций.
4. Скачать четыре файла. Проверить 60 / 10 920 / 21 840 строк данных CSV, 60 сценариев JSON, hashes и run IDs. Повторно открыть сохранённый запуск и сравнить значения.
5. Проверить старые Research Run и G1/G2/G3 Run: ранги, чувствительность с единственной точкой, все нулевые распределения, разрывы при неполных данных. Проверить SVG/PNG четырёх исправленных графиков и семи фигур Experiment 2, сменив τ для линий.
6. В SVG/PNG проверить длинные профили, все серии легенды, подписи/оси, отсутствие обрезания, provenance. PNG проверить при целевом размере статьи; SVG metadata и PNG iTXt содержат полные сведения.

Разработчик не запускал серверы, Docker, браузер или HTTP-проверки работающего приложения. Проверки DOM/SVG выполняются в изолированном jsdom, расчёты — в SQLite unit-тестах. Реальная PostgreSQL и визуальная проверка браузера остаются пользователю.
