A profession and grade form one profile; 7 roles × 2 grades give 14 profiles, with 14 × 13 = 182 distinct directed transitions. Models use **skill** requirements only. ## Epistemic status of inputs

Most inputs were AI-assisted and are not yet expert-verified. Role weights were computed with Python in Colab; some ML-library weights used AI-discovered sources whose exact citations and affected rows have not been supplied. Curriculum discipline names were copied from a real curriculum according to the owner; the document itself has not been checked. Course-skill mappings, Junior/Middle requirements and prerequisite edges were preliminarily generated by AI. These are provenance declarations, not evidence of correctness.

Every original canonical record and raw CSV row starts **Unverified**. CSV `expert`, `survey` and `manual` labels remain raw claims. **Expert Verified** and **Source Verified** are distinct record-level attestations with a named reviewer and assessment/source reference. The app records these claims without authenticating professional credentials or checking external documents. Structural integrity, a DAG, and reproducible arithmetic establish software properties only.

Revisions use copy-on-write snapshots, preserve original source-byte manifests and raw rows, and keep before/after values and provenance. Verification never propagates automatically to aliases, group members, source rows, derived counts, other skills or the entire version. Editing a value resets prior verification unless explicitly reviewed again. Graph interventions in an experiment remain simulated overrides; they are not dataset corrections or verification.

## Inputs and provenance

Let S be canonical skills, G=(S,E) the directed acyclic prerequisite graph, and L=4 the maximum declared proficiency. An edge (u,v) means u is a prerequisite of v. A source profile provides a_s; the target provides t_s. Nonexistent or blank source requirements mean unknown, not proven absence of skill. For the explicitly reported conservative scenario use a_s=0 when unknown, and t_s=4 for a blank target requirement. Skills absent from the target are not direct requirements. All affected unknown IDs are returned separately.

Source grades `junior`, `middle` become `Junior`, `Middle` for display. No proficiency is inferred for source prerequisites, group members, survey aliases, or courses. ANY-style group semantics are ambiguous: all 37 group requirements remain in the DB and audit view but contribute to none of the three models.

One weight file is selected per experiment:

- `role_skill_weights.csv`: use `weight` for the **target role**.
- `skill_weights_by_role_final_v2.csv`: map `skill` through the explicit, case-insensitive `survey_name` dictionary in `skill_mapping.csv`. Exclude explicitly dropped items. For aliases mapping to the same (role, canonical skill), use **MAX(weight_0_1)**. This avoids summing repeated names; it is a declared modeling choice and should be included in sensitivity analysis. `raw_frequency` and `relative_weight` remain audit data and are never added to the selected weight.

Missing weights in the selected source use w_s=1, and the IDs of every fallback are returned. This is a conservative unit-weight fallback, **not** a blend with expert weights from requirements or with the other file. Weights of zero remain zero. M1 can thus be positive when a weighted metric is zero. `role_requirements.weight` and `weight_source` are retained but not used by this protocol.

The supplied final-v2 file has 24 dropped rows, 6 alias collisions, and 4 blank auxiliary `relative_weight` values. Those four rows have valid `weight_0_1` values, so they are usable without imputing the auxiliary field. Every original logical CSV row is stored, including extra columns, and each file's original bytes have a SHA-256 checksum. `docs/dataset-audit.json` contains the full initial audit.

## M1 — Unweighted Skill Gap

For target skill s define d_s = max(0, t_s − a_s). Let D={s: d_s>0}.

**M1 = |D|.** It counts deficient skills, irrespective of the number of missing levels. It does not include prerequisites.

## M2 — Weighted Skill Gap

**M2 = Σ(s∈D) w_s d_s / L.** This is a dimensionless weighted proficiency deficit. The fixed scale L=4 is declared by `skill_levels.csv`. There is no normalization by target role size; interpretation across roles must account for different numbers of requirements.

## M3 — Prerequisite-Aware Weighted Skill Gap

Let C be the transitive union of ancestors of every skill in D, calculated by repeatedly expanding incoming edges. A set ensures shared ancestors are counted once. Expansion continues through an already-satisfied intermediate skill: no unobserved knowledge of earlier ancestors is inferred.

For the chosen minimum prerequisite level p∈[0,4], define:

- unmet prerequisite units: h_s = max(0, p − a_s), for s∈C;
- **additional units**: e_s = max(0, h_s − d_s), taking d_s=0 for s∉D;
- separate additional burden: **B = Σ(s∈C) w_s e_s / L**;
- **M3 = M2 + λB**, where λ∈[0,10] (the UI slider covers 0..3).

Subtracting d_s prevents charging twice for a skill that is both a direct target and an ancestor. If a direct requirement needs fewer units than the prerequisite threshold, only the excess is additional burden. The API returns unscaled B, λB, M2, M3, per-skill d_s/e_s, and the full ancestor closure separately. λ=0 implies M3=M2. With nonnegative weights M3≥M2.

The suggested order is a topological order of the graph restricted to active deficit skills. Kahn's lexicographic algorithm and a deterministic iterative DFS are selectable; they may produce different valid orders but identical scores. Iterative traversal implements recursive dependency semantics without a recursion-depth limit. The order expresses precedence only and is not a validated learning recommendation or course schedule.

## Graph interventions and determinism

Include/exclude overrides are applied to a copy of graph edges; CSVs and stored graphs never change. Unknown nodes, conflicting overrides, nonexistent exclusions, self-loops, and cycles are rejected with HTTP 422. Group requirements remain excluded under all overrides.

For fixed version, parameter values and implementation, results are deterministic: node/edge traversal, summation and profile-pair enumeration are sorted. Kahn uses lexical tie-breaking; DFS uses sorted traversal. Scores are not rounded by the API; the UI rounds only for display. Runtime Python and NetworkX versions are included. Exact dependencies are locked for CI/container builds.

Run provenance contains dataset fingerprint, all file hashes, parameter values (including edge overrides and weight source), implementation version, runtime and a stable run hash. The dataset hash incorporates importer protocol `research-csv-v2`; the run hash binds dataset, canonical record/status hash, resolved parameters, experiment kind (pair/batch) and implementation. Pair and batch therefore have different run IDs even with the same controls. Each exact payload is persisted to PostgreSQL and retrievable by run ID. Runtime is recorded separately; use the locked container for exact runtime replication. No timestamps or randomness enter a score or run identifier. JSON export retains complete provenance; batch CSV includes parameters, overrides, runtime, dataset/run IDs and demo status.

## Scientific limits

Skill weights are not observed hours, cost, probability of success or cognitive effort. Fulfilling prerequisites does not prove recommendation quality. Excluding group requirements removes important profession-specific skills and can understate actual gaps; present this limitation alongside conservative unknown-source assumptions. Fallback weights and alias MAX aggregation also affect rankings. Compare scenarios and weight sources, report exclusion/unknown/fallback counts, and validate recommendations with external outcome data before making empirical claims. The MVP makes no efficacy claim for the conference article.


## Original versus corrected data

The version comparison endpoint applies identical weight source, p, λ, topological algorithm, verification scope, overrides and directed pair population to both snapshots. It returns both run provenance records, per-pair M1/M2/M3 and signed score deltas. These differences measure sensitivity to data revisions; a lower score or additional reviewed edge is not evidence that recommendations improved.

The default `verification_scope=all` includes Unverified records with a visible warning. `verification_scope=verified` selects only Expert Verified / Source Verified requirements, edges and selected-source weights. No source/target reviewed requirement coverage, or no eligible target-role weights, blocks calculation. Missing individual selected weights still follow the explicitly reported unit fallback. Unknown source skills still use the conservative scenario; the reviewed-only score describes a partial reviewed subset rather than complete professional competence. Adding unreviewed simulated edges is disallowed in this scope.

Original immutable versions retain their file-derived IDs; a separate provenance envelope backfills owner-declared origins without changing original rows or previous algorithm artifacts. Corrected version IDs hash the parent ID, canonical record/status content, change request and revision protocol. See [provenance protocol](provenance.md).
