# GitHub Pages — отчёт о готовности

Дата: **2026-11-02**, Asia/Almaty.

**Статус:** статическая версия подготовлена и проверена без запуска приложения. Репозиторий не создавался, commit/push/deploy не выполнялись. GitHub Pages, реальный браузер и Docker не запускались. Публикацию выполняет пользователь по [инструкции](github-pages.md#создание-репозитория-и-публикация-пользователем).

## Аудит и реализация

Модели и графовые алгоритмы перенесены в TypeScript с сохранением определений. FastAPI/PostgreSQL остаются штатной локальной архитектурой. Публичная сборка использует Worker, один source-derived JSON-снимок и сессию в памяти. Новые вычисления выполняются по параметрам посетителя; тестовый эталон Python не включён в runtime.

Dashboard, Skill Graph, Career Transitions, Research Experiments, Research Results (включая Experiments 1–3), Data & Provenance подключены к публичному адаптеру. Административные функции заменены read-only просмотром происхождения записей с объяснением. История настоящей локальной БД не извлекается и не изменяется.

### Сравнение с backend

| Набор | Сценарии | Сравнения направленных переходов |

| **Итого** | **457** | **83 174** |

Проверено **1 076 246 численных полей**. Максимальное наблюдаемое абсолютное расхождение: **3.3306690738754696 × 10⁻¹⁶**. Допуск: atol=1e-10, rtol=1e-10. Навыки, дефициты, замыкания, порядок обучения Kahn/DFS, unknown/fallback списки, ранги, состав/порядок Top-K, изменения рекомендаций и конфигурации проверяются дополнительно. Все сравнения прошли, включая рейтинги 51 исключаемого ребра.

Проверяются все M1/M2/M3, B и λB в каждом фиксированном сценарии, агрегаты, Spearman/Kendall τ-b, нулевые/совпадающие ранги, null для неопределённых коэффициентов. Graph configuration hashes G1/G2/G3 и всех LOO-конфигураций совпали с Python. Execution IDs намеренно другие — с префиксом `browser-` и версией TypeScript-реализации.

Эталон создан существующими backend-функциями в новой SQLite в памяти, без обращения к настоящей БД. Engine получает только опубликованные входы, а не expected results. Отчёт сравнений записывается в игнорируемый `frontend/.parity/comparison.json`. В CI эталон создаётся на Python **3.12**; публикация блокируется при любом провале. Эта удалённая проверка ещё не выполнялась пользователем. В браузерном суммировании отдельно предусмотрены режимы Python 3.11 и 3.12, с фиксированным режимом в provenance.

### Публичная изоляция

Проверены чтение каждого из десяти источников, фильтрация/пагинация records, read-only снимок, блокировка изменения версии, rejection неизвестных профилей/версий/файлов/параметров, ацикличность интервенций и запрет overrides для именованных G1/G2/G3. Новая сессия пуста после прежних вычислений. Тест вычисления запрещает fetch — расчёт и экспорт продолжают работать без сетевого API.

Loader проверяет SHA до расчёта, отказывается от повреждённых байтов и запрашивает только два base-relative JSON. Проверены hash-маршруты всех разделов, прямое открытие публичной provenance-страницы в jsdom, отсутствие API Docs и кнопок записи/верификации. Публичный font import удаляется только при Pages build; CSP ограничивает origin. `.env`, `.parity`, БД и неразрешённые файлы отсутствуют в артефакте. Запросы к localhost/API для вычислений не используются.

## Ограничения и оставшаяся ручная проверка

- Настоящий deployment и HTTPS-страница GitHub Pages ещё не проверены. Workflow подготовлен, но не запускался из этой сессии.
- Реальный Worker в браузере, CSP в целевых браузерах, кнопки загрузки, PNG Canvas и печатная компоновка IEEE требуют ручной проверки. JS-движок, транспортные контракты, DOM/SVG и пути ресурсов покрыты изолированно.
- Локально доступен Python 3.11.9; целевой Python 3.12 проверяется publication workflow перед deploy. Реальная PostgreSQL не запускалась.
- Публично доступен один исходный набор. Исправленные частные версии, редактирование, верификация и постоянная история — только локально. Публичные запуски нужно экспортировать до перезагрузки.
- Память и скорость зависят от устройства, особенно для Experiment 3. Нет фоновой серверной очереди, учётных записей и постоянного пользовательского хранилища.
- Все научные ограничения исходного проекта сохраняются: Unverified, допущения неизвестных уровней, различия шкал весов, отсутствие эмпирического подтверждения качества рекомендаций.
