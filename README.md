# IT Career Graph Lab

Рабочий исследовательский MVP для сравнения карьерных переходов на графе IT-компетенций. Исходные исследовательские CSV (преимущественно подготовлены ИИ, не прошли экспертную верификацию): **71 навык, 51 пререквизит, 7 профессий × Junior/Middle = 14 профилей, 182 направленных перехода**.

React Flow показывает навыки и профессии; FastAPI рассчитывает M1/M2/M3; Recharts разделяет прямой дефицит и дополнительную prerequisite-нагрузку. Dashboard, поиск/категории/транзитивные связи, выбор ролей и уровней, параметры эксперимента, исключение/добавление связей, массовый расчёт, CSV/JSON экспорт и аудит данных реализованы.

## Публичная версия на GitHub Pages

Подготовлен отдельный **browser-compute** режим без FastAPI, внешней БД и регистрации. Он использует опубликованный JSON-снимок десяти CSV, рассчитывает M1/M2/M3 и Experiments 1–3 в TypeScript Web Worker и экспортирует CSV/JSON/SVG/PNG. Входные данные read-only, пользовательские расчёты — только в памяти вкладки. Локальная версия FastAPI/PostgreSQL сохранена.

Целевой адрес: `https://<username>.github.io/ITCareerGraphLab/`; прямые ссылки используют hash, например `#/skills` и `#/results`. `npm run build:pages --prefix frontend` строит статический артефакт; `.github/workflows/pages.yml` проверяет Python/TypeScript parity перед публикацией. **Сайт ещё не опубликован: репозиторий, push и deployment выполняет пользователь.**

Сравнены **457 сценариев / 83 174 результата переходов**; максимальное численное расхождение `3.33e-16` при atol/rtol `1e-10`. Все 42 frontend-теста прошли, локальный и Pages build успешны. Данные Unverified; устойчивость и дефициты — свойства модели, не измерение сложности или доказательство качества рекомендаций.

[Аудит, ограничения и пошаговая публикация](docs/github-pages.md) · [Отчёт сравнительных тестов и перечень файлов](docs/github-pages-verification.md). Приложение, серверы, Docker и браузер разработчиком не запускались.

## Experiment 3 — Data Robustness

Три независимых исследования: неизвестные source-уровни 0/1/2, Final v2 / альтернативный источник / равные веса и 51 leave-one-edge-out G1. Пять контролей τ/λ дают **345 сценариев, 62 790 оценок пар** через существующее математическое ядро. Новый раздел Research Results содержит таблицы M2/M3, heatmap, кривые и рейтинги рёбер, CSV/JSON/SVG/PNG с provenance. Подстановки временные; исходные CSV и Experiment 1/2 не меняются. Веса сохраняют исходную шкалу без перенормировки, её ограничения отображаются явно.

## Experiment 2 — Parameter Sensitivity Analysis

Добавлен фиксированный пакет **G1/G2/G3 × τ [1,2,3,4] × λ [0,0.25,0.5,1,2]**: 60 сценариев по 182 перехода. Используется существующее M3, Final v2 MAX, лексикографический Kahn, All включая Unverified; вмешательств в рёбра нет. Четыре проблемных графика получили SVG-рендер, маркеры одиночных точек и явную обработку отсутствующих значений.

## Происхождение, проверка и исправления

**Исходные данные не являются экспертно подтверждёнными.** Role weights вычислены Python в Google Colab; некоторые ML-веса основаны на источниках, найденных ИИ (точные ссылки пока не предоставлены). Названия дисциплин перенесены из учебного плана по сообщению владельца; это не подтверждает связи дисциплин с навыками. Course-skill mappings, Junior/Middle requirements и prerequisites предварительно сформированы ИИ.

Все импортированные записи получают **Unverified**, включая строки с CSV-метками `expert`, `survey` или `manual`. Эти метки сохраняются как исходные утверждения. Проверка структуры CSV не подтверждает научную валидность.

В разделе **«Версии и верификация»**:

1. Выберите тип записей и фильтр Unverified / Expert Verified / Source Verified.
2. Выберите запись для изменения или проверки; требования и связи можно добавлять и удалять.
3. Укажите автора, причину, название новой версии. Для Verified обязательны имя рецензента и основание проверки — источник или экспертное заключение.
4. Сохраните **новый снимок**: исходная версия и CSV останутся неизменными. Новая версия выбирается только в текущем интерфейсе, active-версия базы автоматически не переключается.
5. Сопоставьте исходную и скорректированную версии для выбранной пары или всех 182 переходов при одинаковых параметрах. JSON сравнения содержит полные результаты и оба run ID.

Статусы — явные заявления названного рецензента, а не автоматическая проверка его квалификации или источника. Source Verified не означает Expert Verified. При изменении значения прежняя проверка сбрасывается в Unverified, если запись явно не проверена заново. Аудит хранит автора, причину, время, значения и provenance до/после; удаление записи из нового снимка не удаляет её из истории.

Каждый запуск сохраняется в PostgreSQL с точной версией, хешем содержимого и статусов, параметрами, реализацией, runtime и результатами. `/api/runs/{run_id}` возвращает сохранённый запуск. Режим **Verified** фильтрует требования, граф и веса; при отсутствии проверенных требований обоих профилей или весов он возвращает ошибку, а не нулевой дефицит. Частично проверенный набор остаётся неполным; допущения об неизвестных уровнях и fallback-весах видимы в результате.

[Протокол provenance и версий](docs/provenance.md). Оценки показывают поведение модели и чувствительность к правкам данных; они не измеряют фактическую сложность перехода и не доказывают качество рекомендаций.

## Быстрый запуск через Docker Compose

Установите и запустите Docker Desktop. Из корня проекта:

```bash
cp -n .env.example .env
docker compose up -d --build
docker compose ps -a
```

Первый запуск скачивает образы/зависимости. Init-сервис запускает Alembic и импортирует `./datasets` в PostgreSQL. Завершение `init` с кодом 0 — нормальное состояние. CSV монтируются read-only; повторный импорт идентичен и не создаёт дубликатов.

- Приложение: http://localhost:8080
- API / Swagger: http://localhost:8000/docs
- Готовность БД и датасета: http://localhost:8000/health/ready
- PostgreSQL/pgvector: localhost:5432, локальные параметры из `.env.example`.

```bash
docker compose logs --tail=80 init backend frontend
docker compose stop
# Продолжить без пересборки
docker compose up -d
```

`stop` сохраняет БД. Данные хранятся в volume `career_pgdata`; не удаляйте volume, если хотите сохранить импортированные версии. Если порты заняты, измените их host-часть в compose. Исходные CSV не перезаписываются.

## Разработка в VS Code

Откройте корневую папку проекта в VS Code. Нужны **Python 3.12**, Node.js 24 и Docker Desktop. Выберите `.venv` как Python Interpreter. В исходном окружении был только Python 3.11; для локального режима установите 3.12, либо используйте уже проверенный контейнер Python 3.12. Терминал 1 — база и backend:

```bash
docker compose up -d db
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.lock
pip install --no-deps -e backend
cd backend
alembic upgrade head
python -m app.cli validate ../datasets
python -m app.cli import ../datasets
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Терминал 2 — frontend:

```bash
cd frontend
npm ci
npm run dev
```

Откройте http://localhost:5173. Vite проксирует `/api` на localhost:8000. При занятом 5173 используйте напечатанный Vite порт. Backend читает переменные окружения или `.env` текущего каталога; стандартный URL соответствует compose. Для другого URL задайте `DATABASE_URL` перед Alembic/uvicorn. Для браузерного клиента на другом хосте можно задать `VITE_API_URL` при сборке и настроить `CORS_ORIGINS` на backend.

## Модели и ограничения интерпретации

- M1 — число навыков с прямым положительным дефицитом.
- M2 — сумма `weight × deficit / 4`.
- M3 — M2 + `λ × дополнительная prerequisite-нагрузка`; транзитивное раскрытие, устранение повторного учёта, Kahn/DFS.

Один источник весов выбирается явно. Final v2 сопоставляется через `skill_mapping.csv`; для совпадающих алиасов применяется MAX(weight_0_1). Веса из `role_requirements.csv` сохраняются, но не смешиваются с выбранным источником. Отсутствующий вес явно заменяется 1 со списком затронутых навыков.

**37 неоднозначных групповых требований исключены**, но сохранены и доступны в разделе «Данные и качество». Неизвестные исходные уровни явно моделируются как 0, неизвестные целевые требования как 4: это консервативный сценарий, а не наблюдаемые знания человека. Веса и оценки не измеряют часы обучения; соблюдение пререквизитов не доказывает качество рекомендаций. В MVP нет анализа резюме, LLM/NLP вызовов и персонализации; предусмотрены интерфейсы расширения и optional extras без тяжёлых моделей.
